# kacarong.kr 개인 작업공간

## 방향 (2026-11-19 사용자와 합의)
- 드라이브가 중심이 아니라 개인 작업공간: 오늘 할 일 · 과제/할 일 · 캘린더 · 노트 · 클라우드(파일함) · 포트폴리오. 혼자 사용.
- 오늘 화면이 로그인 첫 화면: 지난 일, 오늘 날짜의 할 일·과제, 3일 안 마감 과제, 오늘 끝낸 일.
- 과제: 직접 입력(과목·마감일·시간·메모). 헬로 LMS 연동은 되면 나중에.
- 캘린더: 사용자 구글 캘린더와 연동(구글 OAuth에 캘린더 scope 추가 필요). 과제·할 일 날짜도 캘린더에 표시.
- 노트: 노션 같은 블록 편집기. 노트 속 체크박스+날짜 = 할 일(오늘·캘린더에 표시). 편집기 라이브러리 선택은 노트 단계에서.
- 포트폴리오: 공개용과 개인용 구분. 세부는 차차.
- 로그인: 비밀번호 로그인(5번 틀리면 15분 잠금) + 관리자 구글 계정 로그인. 비밀번호는 12자 이상, "kacarong"이 들어가면 안 된다(옛 기본값이 공개 저장소 기록에 있어서, 그런 비밀번호는 맞아도 로그인을 거부). 바꾸기: 작업공간 왼쪽 아래 "비밀번호 바꾸기"(비밀번호 로그인이면 지금 비밀번호 필요) 또는 서버에서 `bun run set-password`. 바꾸면 다른 로그인은 모두 해제.
- 순서: 오늘·과제/할 일(완료) → 캘린더(완료) → 노트(완료) → 클라우드 첨부(완료) → 포트폴리오 공개/개인 구분(1차 완료, 차차 수정).

## 결정 (2026-11-18 사용자와 합의)
- 웹: kacarong.kr = 공개 포트폴리오, /admin = 관리 (관리자 구글 계정 1개만).
- 저장: 사용자 구글 드라이브(유료 400GB). OAuth scope `drive.file` (앱이 만든 파일만). 삭제 = 드라이브 휴지통.
- 업로드: 서버가 resumable 세션만 열고(Origin 헤더 포함), 브라우저가 구글로 직접 PUT (16MB 조각). Cloudflare 100MB 제한·약관 회피.
- 다운로드: webContentLink (본인 구글 로그인 필요). 공유 = "링크가 있는 모든 사용자 보기" 권한. 공개 페이지는 공유된 항목만, 썸네일은 서버가 캐시.
- 파일당 1GB 미만. 앱: 웹사이트 그대로(TWA, 나중에). PC: Flutter Windows 업로드 전용 + 자동 업데이트 (나중에).
- 주소: unifi-site cloudflared 터널(.9, `~/.cloudflared/config.yml`)에 kacarong.kr ingress 추가 → 127.0.0.1:2992.

## 상태
- web/ 1차 구현 (디자인 없음): Bun + bun:sqlite, 의존성 없음. `bun test` = 가짜 구글 서버로 전체 흐름 검증.
- 2026-11-19: 비밀번호 로그인, 할 일·과제(tasks 테이블, /api/tasks, /api/today), /admin 탭(오늘/할 일·과제/파일함). 구글 환경변수 없이도 서버가 뜬다(구글 로그인 404, 파일함은 "연결 안 됨").
- 2026-11-19 실제 구글 계정 점검(운영 DB 복사본 + 로컬 서버 + 헤드리스 크롬): 브라우저→구글 직접 PUT은 16MB 넘는 여러 조각 업로드까지 성공, 308 응답의 Range 헤더도 CORS로 읽혀 /api/uploads/status 없이 이어진다. 공개 켜기 → 로그인 안 한 사람이 보기 링크 200·공개 페이지·썸네일 표시, 공유 끄기 → 보기 401·받기는 구글 로그인 화면·공개 페이지에서 빠짐.

- 2026-11-19 자동 로그인: 로그인 안 된 /admin은 바로 /auth/login(login_hint=ADMIN_EMAIL)으로 가서 구글이 클릭 없이 로그인시킨다. 탭마다 한 번만 시도(sessionStorage autoLoginTried)해 취소·실패 때 반복 없이 로그인 화면, 로그아웃하면 그 기기는 직접 로그인할 때까지 자동 로그인 안 함(localStorage noAutoLogin). 구글에서 취소하면 /auth/callback?error → /admin.
- 2026-11-19 배포: GitHub https://github.com/Kacarong/hanger (공개 저장소, main; 업데이트마다 푸시 — 사용자 요청). 서버 /home/claude/kacarong-folio (GitHub clone) + user systemd `kacarong-folio.service`, env `~/.config/kacarong-folio/env`, 데이터 `~/.local/share/kacarong-folio`. 터널 ingress kacarong.kr → 127.0.0.1:2992, DNS CNAME 덮어씀. 업데이트: `cd ~/kacarong-folio && git pull && systemctl --user restart kacarong-folio`. 서비스 파일(deploy/kacarong-folio.service)이 바뀌면 `cp deploy/kacarong-folio.service ~/.config/systemd/user/ && systemctl --user daemon-reload` 도. 서비스는 Landlock(setpriv)으로 갇혀 있어 코드·데이터 폴더 밖을 못 읽는다(2026-11-19).
- 2026-11-19 디자인: 공개 페이지 = introck.studio 참고(검은 배경, 큰 타이포, 스크롤 등장·이미지 패럴랙스; public/site.css·site.js). 작업공간 = 어두운 사이드바 대시보드(요약 카드 + 표 + 대화상자; public/admin.css). 노트는 메뉴에 "준비 중".
- 2026-11-19 캘린더: 월 달력(6주)에 구글 캘린더 일정 + 날짜 있는 할 일·과제. scope `calendar.readonly`(읽기만, 일정은 서버에 저장 안 함), 구글에서 체크된 캘린더만. `/api/calendar?from&to`(최대 62일), 구글 실패해도 할 일은 나옴. 받은 scope는 settings `granted_scopes`에 저장, 캘린더 scope가 없으면 /auth/login이 prompt=consent로 다시 동의를 받는다. 빈 칸을 누르면 그 날짜로 새 할 일.

- 2026-11-19 보안: 모든 응답에 CSP(스크립트는 자기 파일만, 인라인 스크립트·핸들러 금지, connect-src는 자기+구글 API), X-Frame-Options DENY, nosniff, HSTS, Referrer-Policy. /admin·/api·/auth는 Cache-Control no-store. API의 POST/PATCH/DELETE는 Origin이 이 사이트일 때만.
- 2026-11-19 노트: 편집기 라이브러리 없이 직접 만든 블록 편집기(public/notes.js, 블록마다 textarea라 한글 입력이 안정적). 블록 = 텍스트·제목1~3·체크박스·글머리·번호·인용·코드·구분선. `/` 메뉴, 줄 앞 `# ` `- ` `1. ` `[] ` `> ` ```` ``` ```` `---` 단축, 붙여넣은 여러 줄은 블록으로 나눔, ⋮⋮ 손잡이로 끌어 옮기기·메뉴. 0.7초 뒤 자동 저장(화면 이동·창 닫을 때도). 저장이 실패하면 다른 노트로 넘어가지 않고 초안을 지킨다. notes.version으로 충돌 확인: 다른 탭·오늘 화면에서 바뀐 노트면 PUT이 409, 화면은 자동 저장을 멈추고 "덮어쓰기/바뀐 내용 불러오기"를 묻는다. 노트를 읽는 동안 편집기는 잠근다(inert). notes 테이블(blocks JSON + 검색용 text). 날짜 넣은 체크박스 = tasks 행(note_id, block_id): 노트 저장 때 맞추고, 오늘·할 일 화면에서 체크·수정·날짜 빼기·삭제하면 블록에도 반영. 종류·과목·메모는 할 일 쪽에만. 굵게·링크 같은 글자 꾸밈은 아직 없음.

- 2026-11-19 클라우드 첨부: 노트와 할 일·과제에 파일함 파일을 붙인다. attachments 테이블(target note|task, target_id, file_id, 같은 곳에 같은 파일은 한 번). 파일은 파일함에 그대로 있고 떼면 연결만 없어진다. 노트·할 일·파일이 지워지면(노트 저장으로 사라지는 노트 할 일 포함) 트리거가 첨부도 지운다. API: GET /api/attachments?note=|task=, POST {note|task, fileId}, DELETE /api/attachments/:id. 화면: 노트 제목 아래와 할 일 대화상자에 "클라우드에서 고르기"(파일함 검색 창, 여러 개 연달아) · "새로 올리기"(파일함에 올리고 바로 붙임; 과제면 분류 "과제"). 새 할 일은 고른 파일을 들고 있다가 저장할 때 붙인다. 할 일 목록에 클립 아이콘과 개수.

- 2026-11-19 노션 가져오기(사용자 선택: 노션 페이지·메모를 그대로 사이트로): 노트 화면 "노션에서 가져오기" → 노션 토큰(개인 액세스 토큰 또는 Internal connection의 API token)을 넣으면 서버가 백그라운드로 가져오고 화면은 1초마다 진행을 묻는다(POST/GET /api/notion/import, src/notion.ts, Notion-Version 2022-06-28). 토큰은 저장하지 않는다. 통합에 연결된 페이지마다 노트 하나(제목 앞에 페이지 이모지, 만든·고친 시각도 노션 것). 블록: 문단·제목1~3·체크박스·글머리·번호·인용·코드·구분선은 그대로, 콜아웃→인용, 토글→"▸ 글" + 안쪽 글, 표→"a | b" 줄, 하위 페이지·DB→"📄/🗂 제목" 줄(각자 따로 노트), 열 나누기는 펼침, 링크는 "글 (주소)". 굵게 같은 꾸밈과 들여쓰기는 빠진다. 체크박스 안 날짜 언급은 할 일 날짜(오늘·캘린더). DB 행은 열 값을 "이름: 값" 줄로 맨 위에. 노션에 올린 이미지·파일(1시간 뒤 만료되는 링크)은 파일함에 복사(분류 기타, 태그 노션, 50MB까지 — 서비스 메모리 512MB라서)해 노트에 붙이고, 못 가져오면 노트에 "(가져오지 못함: 이유)". 노션 검색은 빠짐없이 주지 않아서, 하위 페이지(GET /v1/pages)와 DB 행(databases query)도 그 페이지를 품은 페이지에서 따라간다(notion_pages.kids에 기억해 안 바뀐 페이지에서도 따라가고, 여기서 고쳐 건너뛰는 페이지는 블록을 다시 읽어 하위만 찾는다). 통합에 바로 연결한 DB도 검색(value=database)해 행을 모두 읽는다. DB의 파일 칸도 파일함에 복사해 붙인다. 블록은 맨 위 아래로 30단계까지, 넘거나 너무 길면 노트에 표시하고 결과에 "일부만 가져온 페이지"로 알린다. 다시 돌리면 notion_pages/notion_files로 중복 없이: 노션에서 안 바뀐 페이지는 내용을 다시 읽지 않고, 바뀐 페이지는 여기서 안 고친 노트만 갱신(고친 노트는 이름을 알려 주고 건너뜀), 여기서 지운 노트는 되살리지 않음. 파일 복사가 실패한 페이지는 edited=''로 남겨 다음에 다시 시도. 파일은 서명 뺀 주소(source)가 바뀌면 새로 복사하고, 노션에서 바뀌거나 빠진 파일은 노트 첨부에서 뗀다(옛 사본은 파일함에 남음). 가져오기가 만든 첨부는 attachments.by_import=1이고 그것만 뗀다; 사용자가 직접 붙인 첨부는 노션 사본이라도 그대로.

- 2026-11-19 포트폴리오 공개/개인 구분 1차(사용자: "다음 단계 진행, 차차 수정"): 파일마다 포트폴리오 없음/개인용/공개(files.portfolio + public; 공개면 portfolio도 1, 칸이 생길 때 공개 중이던 파일은 portfolio=1). POST /api/files/:id/portfolio {portfolio: none|private|public} (옛 /public 대신). 공개는 링크 공유도 켜고, 링크 공유를 끄면 공개만 빠지고 개인용으로 남는다. /admin/portfolio = 로그인한 나만 보는 내 포트폴리오(공개 페이지와 같은 디자인, 개인용 칩, 아래 띠, noindex, no-store; 로그인 안 했으면 /admin으로). 클라우드 표의 "공개" 칸 → "포트폴리오" 고르기, 사이드바 "내 포트폴리오"·"공개 포트폴리오". 아직 파일만 포트폴리오에 넣을 수 있다(노트는 아님), 순서는 올린 순.
